### ⚠️ Operational issue found this run — needs the owner's attention before Monday's open
This repository has **no `main` branch** — only per-session branches
(`claude/clever-thompson-*`), and none of them merge into a shared branch. Every one
of the last several runs branched directly off the same bootstrap commit


Two problems follow from this:
- **Cadence**: the routine appears to be firing roughly **every hour**, not the
  twice-a-day (AM/PM) cadence the setup guide calls for. That's ~24 runs/day instead
  of 2, all doing nothing productive on a closed weekend market.
- **No shared state**: because no branch is ever merged, every run is only ever
  seeing the original bootstrap state, not what the immediately-prior run did. That
  was harmless this weekend (no fills, no entries happened in any of them), but it
  will not stay harmless once the market reopens Monday: if the schedule keeps firing
  hourly with each run on its own disconnected branch, multiple runs could each think
  they're free to open a new position (nothing yet in "their" branch's state), leading
  to duplicate/uncoordinated entries and lost tracking of protective orders across
  runs. This needs to be fixed (point the schedule at a real shared `main` branch, and
  reduce the frequency) before relying on this for live entries.

This run itself only reconciled and re-verified protections — no trades — so no harm
was done by the branching issue this time.
